\section{非2的幂次方向量加法实现}

前文示例中，每个向量的元素数均为 32 的倍数（如 1024、2048）。这并非巧合——CUDA 的最小执行单元是一个 Warp（32 线程），因此块大小必须是 32 的倍数。当元素数 $N$ 不是 32 的倍数时，线程总数会多于元素数，部分线程空闲，产生利用率损失。本章讨论如何在此约束下选择块大小与网格块数，以最小化空闲线程。

\subsection{Warp 与线程数的约束}

一个 Warp 由 32 个线程组成，是 SM 调度的基本单位。这意味着：

\begin{itemize}
    \item 块大小必须是 32 的倍数，可选值为 $32, 64, 96, 128, \ldots, 1024$。
    \item 无法启动少于 32 个线程的块——若 $N = 16$，仍需启动 32 个线程，其中 16 个空闲，线程利用率仅 50\%。
    \item 小规模数据（如 $N = 16$）更适合在 CPU 端处理，避免主机与设备间数据传输的开销超过计算收益。
\end{itemize}

正因如此，前文刻意选用 1024 而非 1000 作为元素数：当 $N$ 是 32 的倍数时，块大小可整除 $N$，所有线程满载。但这只是理想情况，实际应用中 $N$ 往往任意。

\subsection{块大小与线程利用率}

设 $N = 1000$，对比两种分配方案，如图~\ref{fig:ch32-scenarios} 所示。

\subsubsection{方案一：10 块 $\times$ 100 元素/块}

每块需处理 100 个元素，而 100 不是 32 的倍数。向上取整到最近的 32 倍数得 128（4 个 Warp）：3 个满 Warp（96 线程）加末个 Warp 的 4 个线程，共利用 100 个线程，空闲 28 个。每块线程利用率为：

\[
\frac{100}{128} = 78.125\%
\]

10 个块均如此，全局平均利用率同为 78.125\%。

\subsubsection{方案二：8 块 $\times$ 128 元素/块}

每块处理 128 个元素，恰好等于 4 个满 Warp 的线程数。前 7 个块（处理第 1--896 号元素）线程满载，利用率 100\%。第 8 个块处理剩余 $1000 - 7 \times 128 = 104$ 个元素，仍启动 128 线程，利用 104 个，空闲 24 个。全局平均利用率为：

\[
\frac{7 \times 128 + 104}{8 \times 128} = \frac{1000}{1024} = 97.656\%
\]

方案二以更高的线程利用率（97.656\% vs 78.125\%）显著优于方案一。核心区别在于：方案一每块都浪费 28 个线程，方案二仅末块浪费 24 个，且块数更少（8 vs 10）。

\subsection{波次与执行效率}

线程利用率之外，块数还影响\textbf{波次（Wave）}数量。假设 GPU 有 8 个 SM，每 SM 单波次可驻留 1 个块：

\begin{itemize}
    \item \textbf{方案二（8 块）}：8 个块恰好分配给 8 个 SM，\textbf{单波次}完成，执行时间最短。
    \item \textbf{方案一（10 块）}：前 8 个块占满 8 个 SM 构成第一波次，剩余 2 个块等待第二波次，\textbf{两波次}完成，执行时间约为方案二的两倍。
\end{itemize}

可见，块数的选取不仅影响线程利用率，还直接决定波次数，进而影响总执行时间。应优先选择能使块数对齐 SM 数（或其倍数）的块大小配置。

\subsection{非2幂向量加法示例代码}

处理非 32 倍数 $N$ 的标准做法是：将块大小向上取整为 32 的倍数，网格块数按 $\lceil N / \text{block\_size} \rceil$ 计算，核函数内对越界线程做边界检查。完整示例如下：

\begin{lstlisting}[language=C]
#include <stdio.h>
#include <cuda_runtime.h>

// 非幂次向量加法核函数：越界线程直接返回
__global__ void vector_add(const float* A, const float* B,
                           float* C, int N) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) {
        C[i] = A[i] + B[i];
    }
}

int main() {
    int N = 1000;                    // 非整数倍 Warp 的元素数
    size_t bytes = N * sizeof(float);

    float *h_A = (float*)malloc(bytes);
    float *h_B = (float*)malloc(bytes);
    float *h_C = (float*)malloc(bytes);
    for (int i = 0; i < N; i++) {
        h_A[i] = 1.0f;
        h_B[i] = 2.0f;
    }

    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, bytes);
    cudaMalloc(&d_B, bytes);
    cudaMalloc(&d_C, bytes);
    cudaMemcpy(d_A, h_A, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, bytes, cudaMemcpyHostToDevice);

    // 块大小取 128 (4 个 Warp)，网格块数向上取整
    int block_size = 128;
    int grid_size  = (N + block_size - 1) / block_size;  // = 8

    vector_add<<<grid_size, block_size>>>(d_A, d_B, d_C, N);
    cudaDeviceSynchronize();

    cudaMemcpy(h_C, d_C, bytes, cudaMemcpyDeviceToHost);
    printf("C[0]=%.1f, C[999]=%.1f\n", h_C[0], h_C[N-1]);

    cudaFree(d_A); cudaFree(d_B); cudaFree(d_C);
    free(h_A); free(h_B); free(h_C);
    return 0;
}
\end{lstlisting}

关键点说明：

\begin{itemize}
    \item \texttt{block\_size = 128} 是 32 的倍数（4 个 Warp），满足硬件约束。
    \item \texttt{grid\_size = (N + block\_size - 1) / block\_size} 即 $\lceil N / \text{block\_size} \rceil$，本例 $N = 1000$ 得 \texttt{grid\_size = 8}，对应方案二。
    \item 核函数中 \texttt{if (i < N)} 是越界检查：末块中索引 $\geq N$ 的线程直接返回，不写入 \texttt{C}，避免越界访问。这些线程虽空闲但不会导致错误。
    \item 调整 \texttt{block\_size} 即可在方案一与方案二之间切换：取 100 需向上取整为 128（方案一的每块配置），但网格块数变为 $\lceil 1000/100\rceil = 10$，利用率下降。
\end{itemize}

\subsection{本章小结}

\begin{itemize}
    \item 块大小必须是 32 的倍数；当 $N$ 不是 32 的倍数时，需向上取整线程数并做越界检查。
    \item 块大小与网格块数的选取直接影响线程利用率：应使每块处理的元素数尽量接近块大小的整数倍，减少空闲线程。
    \item 块数还应与 SM 数对齐以减少波次：单波次完成的配置执行时间最优。
    \item 核函数中的 \texttt{if (i < N)} 越界检查是处理任意 $N$ 的标准模式，适用于所有非对齐规模的向量运算。
\end{itemize}
