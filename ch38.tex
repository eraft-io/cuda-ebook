\section{CUDA GPU 并行编程：向量归约代码解析与性能剖析}

本节将讲解向量归约（Vector Reduction）的完整代码。首先编写一个在 CPU 端执行向量归约的函数，用于验证 GPU kernel 输出的正确性。具体方法是将 GPU kernel 的输出与 CPU 函数的输出进行比较。由于 CPU 函数逻辑简单且结果可验证，因此可以作为基准。

\subsection{CPU 端归约函数}

向量归约的输入是一个包含多个元素的向量，输出是一个与输入类型相同的标量值，即所有元素的总和。因此 CPU 函数的返回类型为 float。函数命名为 \texttt{cpu\_reduce}，参数与 GPU kernel 一致。函数通过 for 循环遍历所有元素并累加，最终返回 sum 变量。

\begin{lstlisting}
float cpu_reduce(float* input, int n) {
    float sum = 0.0;
    for (int i = 0; i < n; i++) {
        sum += input[i];
    }
    return sum;
}
\end{lstlisting}

\subsection{CUDA 应用程序的七个步骤}

接下来编写 main 函数。回顾之前章节中介绍的 CUDA 应用程序七个步骤：

\textbf{第一步：在主机和设备上为向量分配空间。}

本例仅有一个输入向量，需分别在 CPU 和 GPU 上为其分配空间。设备端使用 \texttt{d\_input}，主机端使用 \texttt{h\_input}。主机端使用 C++ 的 \texttt{new} 操作符分配，元素数量设为 $n = 1024 \times 1024$。

\begin{lstlisting}
float* d_input;
float* h_input = new float[n];
\end{lstlisting}

设备端使用 \texttt{cudaMalloc} 分配显存。需注意，分配的大小是字节数而非元素个数，因此需用 \texttt{size\_t size = n * sizeof(float)} 计算。每个 float 占 4 字节，总字节数为元素数量乘以 4。

\begin{lstlisting}
size_t size = n * sizeof(float);
cudaMalloc(&d_input, size);
\end{lstlisting}

\textbf{第二步：在主机端初始化输入向量。}

使用 for 循环将每个元素初始化为其索引值，并通过 \texttt{static\_cast<float>(i)} 进行类型转换。

\begin{lstlisting}
for (int i = 0; i < n; i++) {
    h_input[i] = static_cast<float>(i);
}
\end{lstlisting}

\textbf{第三步：将主机数据复制到设备端。}

使用 \texttt{cudaMemcpy} API，参数依次为目标地址（设备端 \texttt{d\_input}）、源地址（主机端 \texttt{h\_input}）、字节数（size）和传输方向（\texttt{cudaMemcpyHostToDevice}）。

\begin{lstlisting}
cudaMemcpy(d_input, h_input, size, cudaMemcpyHostToDevice);
\end{lstlisting}

\textbf{第四步：配置 kernel 启动参数。}

设定 block size 为 256。grid size 需确保 block 数量乘以 block size 不小于 n。通用公式为：

\begin{lstlisting}
int blocksize = 256;
int gridsize = (n + blocksize - 1) / blocksize;
\end{lstlisting}

当 $n = 1024 \times 1024$、blockSize = 256 时，gridSize = 4096。公式 \texttt{(n + blockSize - 1) / blockSize} 可解决 n 不是 blockSize 整数倍时的向上取整问题。

\textbf{第五步：调用 CPU 函数获取基准结果。}

在启动 GPU kernel 之前，先调用 CPU 函数获取归约结果，以便后续与 GPU 输出进行比较。

\begin{lstlisting}
float sum = cpu_reduce(h_input, n);
std::cout << sum << std::endl;
\end{lstlisting}

\textbf{第六步：启动 GPU kernel。}

根据前一节的分析，向量归约需要多次启动 kernel。第一次 kernel 处理全部 $n$ 个元素，每个 block 产生一个部分和。第一次执行时 grid size 为 4096，因此产生 4096 个部分和。

\begin{lstlisting}
reduce_in_place<<<gridsize, blocksize>>>(d_input, n);
cudaDeviceSynchronize();
\end{lstlisting}

\texttt{cudaDeviceSynchronize()} 用于确保 CPU 等待 GPU kernel 执行完毕后再进入下一步。

第二次 kernel 以 4096 个部分和作为输入。block size 仍为 256，grid size 为 $4096 / 256 = 16$，即第二个 kernel 在 16 个 block 上执行，产生 16 个部分和。

\begin{lstlisting}
reduce_in_place<<<4096 / blocksize, blocksize>>>(d_input, 4096);
cudaDeviceSynchronize();
\end{lstlisting}

第三次 kernel 仅需 1 个 block，因为待处理元素仅 16 个，不足一个 block（256 线程）。

\begin{lstlisting}
reduce_in_place<<<1, blocksize>>>(d_input, 16);
cudaDeviceSynchronize();
\end{lstlisting}

\textbf{第七步：将结果从设备复制回主机并释放资源。}

最终结果存储在 \texttt{d\_input[0]}。仅需复制一个 float 元素（4 字节），而非整个向量。

\begin{lstlisting}
cudaMemcpy(h_input, d_input, sizeof(float), cudaMemcpyDeviceToHost);
std::cout << "GPU output: " << h_input[0] << std::endl;

cudaFree(d_input);
delete[] h_input;
\end{lstlisting}

完整的 main 函数代码如下：

\begin{lstlisting}
#include <iostream>
#include <cuda_runtime.h>

__global__ void reduce_in_place(float* input, int n) {
    int tid = threadIdx.x;
    int index = blockIdx.x * blockDim.x + threadIdx.x;

    // Perform in-place reduction within each block
    for (int stride = 1; stride < blockDim.x; stride *= 2) {
        __syncthreads();  // Ensure all threads have completed the previous iteration

        if (tid % (2 * stride) == 0 && index + stride < n) {
            // Perform reduction and store the sum back in place
            input[index] += input[index + stride];
        }
    }

    // Store the block's reduced result in the first position of this block's portion
    if (tid == 0) {
        input[blockIdx.x] = input[blockIdx.x * blockDim.x];  // Write the reduced sum for this block
    }
}

float cpu_reduce(float* input, int size) {
    float sum = 0.0f;
    for (int i = 0; i < size; ++i) {
        sum += input[i];
    }
    return sum;
}

int main() {
    int n = 1024 * 1024;  // Number of elements
    size_t bytes = n * sizeof(float);

    // Host memory allocation
    float* h_input = new float[n];
    float* d_input;

    // Initialize input array
    for (int i = 0; i < n; i++) {
        h_input[i] = static_cast<float>(i + 1);  // Initialize from 1 to n
    }

    // Device memory allocation
    cudaMalloc(&d_input, bytes);

    // Copy data from host to device
    cudaMemcpy(d_input, h_input, bytes, cudaMemcpyHostToDevice);

    // Launch the reduction kernel multiple times
    int blockSize = 256;  // Number of threads per block
    int gridSize = (n + blockSize - 1) / blockSize;  // Number of blocks
    // Calculate the sum using the CPU function for verification
    float total_sum = cpu_reduce(h_input, 1024 * 1024);
    std::cout << "Total sum (CPU): " << total_sum << std::endl;
    // Perform iterative reduction until we have one block left
    reduce_in_place << <gridSize, blockSize >> > (d_input, n);
    cudaDeviceSynchronize();  // Ensure kernel execution completes
    reduce_in_place << <16, blockSize >> > (d_input, 4096);
    cudaDeviceSynchronize();  // Ensure kernel execution completes


    // Final reduction when gridSize is 1
    reduce_in_place << <1, blockSize >> > (d_input, 16);
    cudaDeviceSynchronize(); 
    // Copy the final result back to the host (the sum should be in h_input[0])
    cudaMemcpy(h_input, d_input, sizeof(float), cudaMemcpyDeviceToHost);

    // Print the result
    std::cout << "Final sum (GPU): " << h_input[0] << std::endl;

    

    // Free memory
    cudaFree(d_input);
    delete[] h_input;

    return 0;
}

\end{lstlisting}

\subsection{精度差异说明}

运行程序后，CPU sum 和 GPU sum 的值非常接近，但小数点后可能存在微小差异。这是由于 GPU 与 CPU 使用了不同的浮点精度。若将数据类型从 float 改为 double，两者的值将完全一致，因为 double 的精度高于 float。读者可自行验证。此外，可借助 C++ 模板（templates）机制实现数据类型的灵活切换，无需在代码中逐一修改。

在 View 选项卡中展开各部分，可观察到以下关键指标：

\begin{itemize}
    \item \textbf{SM 利用率：} 约 74\%，表明计算资源利用较为充分。
    \item \textbf{Memory Throughput：} 仅约 9\%，说明相比于内存，计算资源使用过多，存在计算受限的特征。
    \item \textbf{缓存命中率：} L1 命中率 91\%，L2 命中率约 80\%。这与向量加法（命中率接近 0\%）形成鲜明对比。原因在于向量归约中每个元素在多个步骤中被重复使用，产生了数据重用（Data Reuse），从而带来缓存命中。
    \item \textbf{算术单元利用率：} ALU 和 FMA 有较高的利用率数值，而双精度利用率为零（因为使用的是 float 类型）。若将 float 改为 double，则会在双精度利用率一栏中看到相应数值。
    \item \textbf{时间轴图：} 展示了执行过程中活跃 block 数量的变化，可用于识别瓶颈所在。
\end{itemize}
