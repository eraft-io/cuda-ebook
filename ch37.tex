\section{仅使用全局内存的向量归约（基准版本）}

本节开始讲解"向量归约"（Vector Reduction）应用程序。需要说明的是，本节仅涉及该主题的第一部分，后续章节还将介绍针对该应用的多种优化技术。因此，本节内容不仅对于理解向量归约至关重要，也是掌握诸多优化技术的基础。建议大家认真学习本节内容，因为它在许多其他应用中同样适用。例如，在矩阵乘法中就需要用到归约过程或归约操作。因此，理解归约的含义及其优化方法十分必要。

首先回顾向量加法。在之前的章节中，执行的操作是将两个向量的所有对应元素相加并将结果存入第三个向量。例如，将向量 A 的第 15 个元素与向量 B 的对应元素相加，结果存入向量 C 的相同位置。在该应用中，使用的线程数量等于元素数量，因为每个线程负责处理一个索引。作为练习，读者可尝试使用仅为一半数量的线程来完成向量加法：例如对于 512 个元素，不使用 512 个线程，而仅使用 256 个线程，让每个线程处理两个元素。

\subsection{向量归约的定义}

与向量加法不同，向量归约只涉及单个向量。假设有一个名为 input 的输入向量，其索引从 0、1、2 一直到 16。目标是将该向量中的所有元素相加，并将最终的总和存储在第一个位置（即索引 0 处）。如图所示，41 即为所有元素的总和。这就是向量归约的含义，它比向量加法复杂得多。

\subsection{归约的执行流程}

第一步，设定线程数量等于元素数量。假设有 16 个元素，则使用 16 个线程，索引为 0 到 15。这可以视为一个包含 16 个线程的线程块配置。关键点在于：一半的线程将处于空闲状态，不执行任何操作。

原因如下：注意区分索引和线程 ID，线程 ID 也从 0 到 15。以第一个线程（ID=0）为例，它的任务是将第一个元素与第二个元素相加，并将结果存回第一个位置。后续每对元素也是如此：线程 0 执行 input[0] = input[0] + input[1]，即处理元素 tid 和 tid+1。跳过线程 1，直接看线程 2：线程 2 执行 input[2] = input[2] + input[3]，同样处理 tid 和 tid+1。

线程 1 在此步骤中是不需要的，因此一半的线程会处于空闲状态。既然只需要一半的线程，为何不直接启动 8 个线程？因为向量归约并非一步完成，而是需要重复多次，直到所有元素累加为一个值。减少线程数会使代码变得复杂。

如图所示，"一半线程空闲"的原因在于：每个工作线程处理两个相邻元素，因此奇数 ID 的线程（如 1、3、5 等）在第一阶段无需工作。此步骤必须对新产生的值重复执行，因为在第一步之后，并未得到所有元素的总和，只是完成了相邻元素的配对相加。例如，11 和 7 相加的结果需要在下一步中继续参与运算。

第二步所需的线程数更少。第一步有 16 个元素，第二步仅剩 8 个有效元素（其余已在第一步中被合并）。将这 8 个元素两两相加仅需 4 个线程。编写代码时需要针对每一步进行相应的索引计算，因为每步使用的线程数都在递减。这也正是"归约"名称的由来：既指将所有元素归约为一个值，也指每步所需的操作数和线程数不断减半。

继续演示：将 11 与 7 相加，结果存入原位；-2 与 8 相加，结果存入原位，依此类推。第三步所需的有效元素进一步减少。第一步 16 个元素用 8 个活跃线程，第二步 8 个元素用 4 个线程，第三步 4 个元素仅需 2 个线程（线程 0 和线程 8）。线程 0 将前两个结果相加存入索引 0，线程 8 将后两个结果相加存入索引 8。最后一步仅需一个线程将索引 0 和索引 8 的值相加，最终结果存入 input[0]。这就是完整的归约流程。

\subsection{多块归约与跨块同步问题}

在实际 CUDA 编程中，需要处理线程、块 ID、网格大小、块大小与向量大小之间的映射关系。这种模式被称为"基于树的方法"（Tree-based Approach），因为其执行路径呈树状分支结构。从主向量开始，每经过一个阶段，有效元素数量减半，直至最终只剩一个包含总和的元素。

可以将整个向量划分为多个块，每个块负责处理其中一个数据块（Chunk）。例如，将向量分为两个块：块 1 处理前 8 个元素，块 2 处理后 8 个元素。每个块独立执行归约操作，最终各自产生一个结果。但这些结果并非最终总和，而是"部分和"（Partial Sums）。

例如，块 1 的部分和为 24，块 2 的部分和为 17。要得到最终结果，必须将所有块的部分和再次相加。然而，无法简单地启动第三个块来同步并累加这些部分和，因为 CUDA 不支持跨线程块的全局同步。虽然存在线程束级、内核级甚至指令级的同步机制，但不存在块级同步。如果在所有前置块完成之前就开始执行汇总块，可能会读取到尚未更新的部分和，导致错误。NVIDIA 的文档也明确指出，由于硬件开销巨大，GPU 不提供跨块的全局同步。

\subsection{多内核解决方案}

解决方案是使用两个内核（Kernel）。第一个内核执行所有数据块的归约操作；利用 CUDA 的内核级同步机制，确保第一个内核完全执行完毕后，再启动第二个内核。第二个内核以第一个内核输出的部分和作为输入，计算最终总和。根据向量大小，可能需要三个或更多内核，但本例中两个即可。

两个内核的配置可能不同。例如，第一个内核可能有 8 个块，而第二个内核仅需 1 个块（因为只有 8 个部分和需要累加）。虽然本例中两个内核的块大小相同，但网格大小（Grid Size）是不同的。

\subsection{内核代码实现}

下面进入代码讲解。右侧展示了归约的所有步骤，左侧是一段简化的初始代码（并非最终正确版本），将逐步完善。首先，\texttt{\_\_global\_\_} 关键字定义了一个 GPU 内核。GPU 内核不能有返回值，若需将结果传回 CPU，必须使用 memcpy API。内核命名为 \texttt{reduce\_in\_place}，表示在原向量上进行归约。参数包括向量指针 input 和向量大小 n，传入 n 是为了防止越界访问，避免内存违规。

核心计算公式为 input[index] += input[index + 1]。假设 16 个线程，当 tid=0 时，执行 input[0] += input[1]；当 tid=1 时，执行 input[1] += input[2]。但在下一步中，索引 1 处的值已不再需要，只有索引 0、2、4 等偶数索引的值会被使用。因此 tid=1 的计算虽然是合法的，却是冗余的，浪费了资源。需要添加过滤器，仅允许偶数 ID 的线程（0, 2, 4, 6...）执行该指令。

\begin{lstlisting}
__global__ void reduce_in_place(float* input, int n) {
    int index = blockIdx.x * blockDim.x + threadIdx.x;

    input[index] += input[index + 1];
}
\end{lstlisting}

过滤偶数 ID 的方法是使用取模运算：

\begin{lstlisting}
if (tid % 2 == 0)。当 tid=0 时，0%2==0 成立，执行指令；当 tid=1 时，1%2==1 不等于 0，跳过指令。
\end{lstlisting}

此外，还需要边界检查。当 tid=15 时，index+1 为 16，超出了大小为 16 的向量范围（最大索引为 15），会导致内存越界。因此必须添加条件 if (index + 1 < n)。综合两个过滤器，代码为：

\begin{lstlisting}
__global__ void reduce_in_place(float* input, int n) {
    int tid = threadIdx.x;
    int index = blockIdx.x * blockDim.x + threadIdx.x;

    if (tid % (2 * 1) == 0 && index + 1 < n) {
        input[index] += input[index + 1];
    }
}
\end{lstlisting}

然而，这段代码仅能完成第一步。为了完成整个归约过程，需要使用循环。观察发现，每一步的"步长"（Stride）在不断变化：第一步步长为 1（处理相邻元素），第二步步长为 2（间隔一个元素），第三步步长为 4，第四步步长为 8。通式为 stride = stride * 2，初始值为 1。循环终止条件为 stride < blockSize。同时，过滤器中的取模因子也应随步长变化，改为：

\begin{lstlisting}
tid % (2 * stride) == 0。
\end{lstlisting}

最终的内核代码如下：

\begin{lstlisting}
__global__ void reduce_in_place(float* input, int n) {
    int tid = threadIdx.x;
    int index = blockIdx.x * blockDim.x + threadIdx.x;

    for (int stride = 1; stride < blockDim.x; stride *= 2) {
        __syncthreads(); // Ensure all threads have completed the previous step

        if (tid % (2 * stride) == 0 && index + stride < n) {
            input[index] += input[index + stride];
        }
    }

    // Store the block's reduced result in the first position of this block
    if (tid == 0) {
        input[blockIdx.x] = input[blockIdx.x * blockDim.x]; // Write the partial sum
    }
}
\end{lstlisting}

\subsection{部分和的收集}

当有多个块时，每个块的归约结果位于该块数据的起始位置（如块 1 的结果在索引 0，块 2 的结果在索引 8）。为了在第二个内核中连续处理这些部分和，需要将它们移动到向量的前端连续位置。例如，将索引 8 处的值移到索引 1 处。这通过 input[blockIdx.x] = input[blockIdx.x * blockDim.x] 实现（假设块大小一致且紧凑排列）。第二个内核只需处理数量等于块数的元素。

本节讲解的内核仅使用了全局内存，未涉及共享内存或 Shuffle 指令等优化技术。这些高级优化将在后续章节中详细介绍。
