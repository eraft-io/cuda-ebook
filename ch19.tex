\section{CUDA 课程项目三：向量加法（Vector Addition）讲解}

本章将解释第三个项目——向量加法（Vector Addition）。向量 A 包含 1024 个元素，索引范围从 0 到 1023。在本项目中，
假设有两个向量，每个向量包含 1024 个元素。类似地，有向量 B，如图所示。当前的任务是将这两个向量相加，结果存储在向量 C 
中，如图所示。这意味着向量 A 的第一个元素将与向量 B 的第一个元素相加，加法操作以逐元素的方式进行，结果存储在 C 的零位
置，即 C 的第一个元素。

\subsection{CPU 上的向量加法}

在深入 GPU 代码之前，先展示一下这个应用在 CPU 上的代码。在每次迭代中，将向量 A 和向量 B 的对应元素相加，并将结果保存
在向量 C 中。如图所示，这个过程简单地涉及编写一个 for 循环来遍历所有 1024 个元素。以上就是关于在 CPU 上运行向量加法的
全部内容。需要注意的是，for 循环的迭代是顺序执行的，而非并行的。

基于之前的讨论，第一步是为 GPU 应用确定块和线程的数量。这里首先假设只使用一个块和 1024 个线程。根据这个信息，这个块的 
ID 将为 0，而线程 ID 的范围将从 0 到 1023。这个选择使线程数量与每个向量中的元素数量一致。每个向量有 1024 个元素，这意味
着每个线程 ID 等于向量中某个元素的索引。稍后将会用到这个信息。

现在写出第一个元素的加法操作，仅仅是第一个元素。一个小例子看起来是这样：C 的零位置等于 A 的零位置加上 B 的零位置。考虑
到块和线程的 ID，在本例中只有一个块，ID 为 0，因此块 ID 没有实际用途。这个模式被复制到第二个元素、第三个元素，依此类推
，覆盖这些向量中的所有元素。然而线程 ID 表明，正如前文所述，它们等于元素的索引。这个观察使我们能够有效地为每个线程分配
不同的元素。线程 ID 范围从 0 到 1023，与元素的索引范围相同。例如，线程 0 可以与第一个元素对齐，第二个线程可以与第二个
元素对齐，以此类推。

\subsection{CUDA 核函数实现}

理论部分已讲完，现在的问题是如何将其转化为 CUDA 代码。实际上答案非常简单，实现目标所需的代码很简洁，这里只需要一个操作——
加法操作。这意味着一个操作将由多个线程执行。在展示的代码中，声明了一个名为 \texttt{vectorAdd} 的 GPU 核函数（kernel）。
在接下来的指令中，对每个元素执行加法操作。在核函数的第一条指令中，首先读取线程 ID，其范围从 0 到 1023。这里的每个块以
及整个 GPU 的线程总数等于 1024。这里的操作将被执行多次，次数等于线程数。线程 ID 控制着将要执行加法操作的元素。这 
1024 条指令将被分配给 GPU 中不同的核心，以便并行执行。这意味着这条指令将被隐式地执行 1024 次，每次都有一个不同的线程 
ID。正如这部分提到的，在 GPU 上相加这两个向量的核函数只需要展示的 1 到 2 条指令，无需任何循环。与在 CPU 上运行相同函数
时需要编写循环不同，线程 ID 会显式地变化以遍历不同的元素，因此不需要循环。

在打开 Visual Studio 并检查代码及其执行之前，先回顾一下任何 CUDA 应用的基本步骤。以本应用为例，任何 CUDA 应用的第一
步都是为输入和输出数据分配空间。我们需要为三个向量 A、B 和 C 分配内存，并确保在主机（CPU）和设备（GPU）上都为这些向量
分配了空间。例如，如这三部分所示，这些是实现第一步目的所需的指令。这里分配了一些指针，三个用于 CPU 分配，另外三个用于 
GPU 分配。然后使用这些指针和 \texttt{malloc} 函数，在 CPU 的内存中为三个向量分配所需空间。类似地，使用 
\texttt{cudaMalloc} 函数在 GPU 内存中为这些向量分配空间。

如图所示，下一步是初始化输入。在本例中，这意味着为向量 A 和 B 赋值，因为如果没有先为它们填充值，就无法执行 A 和 B 
的加法。这是一个 CPU 步骤，意味着它将在 CPU 上执行，而非 GPU。这就是为什么使用 for 循环来执行这一步。如图所示，for 
循环遍历向量 A 和 B 的所有元素，然后在每个元素中存储值。

第三步涉及将这些初始化的 A 和 B 值传输到 GPU。因为目标是在 GPU 上执行加法操作，这一步可以通过 2 个 API 或两条指令
实现。有必要将输入数据移动到 GPU 的内存中。第一个是复制向量 A 的数据，第二个用于复制向量 B 的数据。一旦数据进入 GPU 
内存，就可以调用向量加法核函数。如这里的指令所示，这个核函数处理 A 和 B 的元素以执行加法操作，并将结果保存在向量 C 中
。正如前文讨论的那样，这条指令包含三个主要部分：核函数名称、核函数配置（即块和线程的数量），以及核函数的输入参数。

在结果安全存储在 GPU 内存中之后，下一步是将它们传输回 CPU 内存。在那里可以打印它们，或将它们发送到另一个阶段，或发送到
另一个 GPU 核函数进行进一步计算等。这只是一个内存复制操作，但这次的配置是从 GPU（设备）到 CPU（主机）。如图所示。这
个过程的最后一步是释放之前在 CPU 和 GPU 上分配的内存空间，这确保了高效的资源管理，并避免内存泄漏。

\subsection{完整代码解析}

如图所示，代码以每个向量的大小开始，大小等于 1024 个元素。每当需要改变应用中向量的大小时，只需更改这个值。这就是为什么
需要在应用开始时预定义大小。然后是 GPU 核函数，我们知道这是一个 GPU 核函数而非 CPU 函数，因为有 \texttt{\_\_global\_\_} 
修饰符，这意味着这些指令将在 GPU 端执行，而非 CPU 端。核函数名称是 \texttt{vectorAdd}，它接受四个值：向量 A、向量 
B 作为输入，向量 C 作为输出（存储结果的地方）。还有一个变量 N，实际上等于大小（1024）。这里暂不详细解释 N 变量，将在
后续章节中说明。

然后是两条指令，实际上可以将它们合并为一条指令，但这里保留两条以便为后续更复杂的应用做准备。这里是读取线程 ID，有 
1024 个线程，这个变量将包含线程 ID 的值，不同的线程 ID 将用于遍历这些向量中的所有元素。线程 ID 将从 0 到 1023。这就
是 GPU 核函数，它非常简单。

然后是主函数的开始。第一步是分配一些指针以供使用，下一步是在 CPU 端和 GPU 端分配空间。例如这三个向量，将用于在 CPU 
内存上为向量 A、向量 B 和向量 C 分配空间。使用 \texttt{malloc} 函数来分配这些空间。需要注意的是，这是每个向量的大小
，预定义的大小并不正好是 1024，因为乘以了整数值的大小（\texttt{sizeof(int)}），这就是使用 \texttt{malloc} 函数的
方式。总之需要具备一定的 C 语言基础才能理解这里的一切。

然后使用另外三个指针在 GPU 内存上分配空间。这三个指令是为在 GPU 内存上分配三个向量所需的空间，分别是第一个向量、第二
个向量和第三个向量，它们都使用相同的大小。

下一步是初始化向量 A 和向量 B。不需要初始化向量 C，因为这是将要存储结果的地方。这里使用一个 for 循环来遍历向量 A 和向
量 B 内的所有元素，存储一些值。这个 for 循环的结束条件是 1024。例如在 A 中存储 I 的值，I 从 0 到 1024。第一个元素将
等于 0，第二个元素将等于 1，最后一个元素将等于 1023，以此类推。如果 I 等于 0，B 的值将等于 1023。B 的值等于 1024 
减去 I 值。这非常简单，不需要关注值本身，可以用任何想要的值来初始化 A 和 B。

一旦初始化了 A 和向量 B 的值，就需要将这些值从 CPU 传输到 GPU。因为这里的 A 和 B 在 CPU 端，不在 GPU 端。A 和 B 
是 CPU 的，\texttt{d\_A}、\texttt{d\_B} 是 GPU 端的。需要做的就是使用 \texttt{cudaMemcpy} 函数，意思是 CUDA 的
内存复制操作。将从主机复制到设备，主机指的是 CPU，设备指的是 GPU，这就是这条指令的用法。将从变量 A 复制到变量 
\texttt{d\_A}，从 CPU 到 GPU。要复制的数据量等于这个大小。向量 B 也是如此，将移动数据，大小等于这个值，从 CPU 到 
GPU，从变量 B 到 GPU 上的变量 \texttt{d\_B}。不需要复制向量 C，因为向量 C 将存储结果。

一旦通过这两个指令或 API 将数据放入 GPU 内存，就需要执行向量加法核函数 \texttt{vectorAdd}。在这里启动，调用 
\texttt{vectorAdd} 核函数，它将执行这里的这两条指令。使用的配置是一个块，每个块 1024 个线程。并且核函数将使用向量 A、
向量 B、向量 C 以及所有这些向量的大小作为输入。一旦调用这个函数，执行将从 CPU 端转移到 GPU 端。它会执行所有线程，这意
味着对所有元素执行加法操作，并将结果存储在 C 中。

一旦在 C 中有了结果，这一步之后，就需要将数据从 GPU 内存复制回 CPU 内存。如所示，将结果复制回主机，只是为了将这部分
与这部分进行比较。\texttt{cudaMemcpyDeviceToHost}，这里有 \texttt{HostToDevice}。要传输或移动的数据量等于这个
大小，并且从 GPU 向量移动到 CPU 向量。需要注意这里的顺序，这里从 GPU 到 CPU。

一旦在向量 C 上有了数据，而向量 C 在 CPU 端，就可以打印结果 C 值。这里使用 for 循环遍历所有元素并打印 A、B 和 C 
值。如所示，A 加 B 等于 C。一旦打印完结果，就需要释放两端所有分配的空间，CPU 端和 GPU 端。如所示，这里使用 
\texttt{cudaFree} 释放 GPU 的内存，CPU 端也是一样，但只使用一个叫 \texttt{free} 的函数。它们非常相似，这里的 
\texttt{free}，这里的 \texttt{cudaFree}。但因为这将释放 GPU 上的空间，这里使用了 CUDA 术语。
