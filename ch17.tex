\subsection{cudaDeviceSynchronize}

正如我之前告诉你的，我会在本节末尾解释如何解决这个问题。但无论如何，你现在就可以知道原因：在 CPU一侧，当进入主函数时
，CPU 会逐条执行指令，直到主函数结束。它执行完这条指令后会立即执行下一条指令，而不会等待 GPU完成。当 CPU 到
达这里——这条命令或这条指令，也就是启动 GPU 核函数时——CPU 会启动或发送该核函数到GPU，但 CPU 并不会等
待 GPU 核函数的输出结果。这就是为什么我们需要这里的这条指令，即\texttt
{cudaDeviceSynchronize()}。这里的“同步”意味着我们需要 CPU 等待，直到GPU 完成这个核函
数。

我们可以在这里实现这一点。例如，让我到这里来，稍等一下，再输入一次编译命令。现在我们有了一个可执行文件，但这次使用了同步
指令。如你所见，我们得到了输出。现在让我们运行该项目。让我再重复一次，以确保我刚才所说的验证无误。我们开始编译，我们有输
出；再次运行，再运行一次，没有输出；再运行一次，我们有输出。有时候会输出，有时候则不会。再运行一次，但当你使用同步时，CPU肯定会在这里等待，我们肯定会在终端上看到输出。让我再运行一次，如你所见，没有输出，好吗？


但如果我们从这里移除这一行，然后保存、编译并运行，在所有运行中，我们都会……等等，不对。如果我们保留同步，在所有运行中都
会在终端上看到输出。让我们看看，在这里不可能出现没有输出的情况。我们有输出。希望你现在理解了这里的同步机制。这不仅适用于
Linux，也适用于 Windows，这并不限于 Linux 系统。
