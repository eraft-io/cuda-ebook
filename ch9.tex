\section{半精度、单精度与双精度运算}

本章将介绍 GPU 中不同的数据类型及其大小。在开始前需要说明一点：理解数据类型和大小，就像在工具箱中选择合适的工具一样，是
高效且准确完成任务的基础。在 GPU 计算领域，与 CPU 类似，我们会根据需求采用不同的方式来存储数值。先从整数开始：对于整
数，我们可以使用 8 位、16 位、32 位甚至 64 位，位数越多能存储的数值就越大。例如，一个 8 位无符号整数可以存储 0 到 255 
之间的值；如果是有符号变量，范围则为 -128 到 127。

\subsection{整数与浮点类型}

对于 64 位整数，可以存储大得多的数值，最高约 $1.8 \times 10^{19}$（约 1800 亿亿）。当处理带小数点的数字时，则会使用浮点表示法
：16 位为半精度，32 位为单精度，64 位为双精度。

在 C 或 CUDA 编程语言中，用 int 声明变量使用 32 位；将 int 替换为 long long，则通常使用 64 位。类似地，用 float 声明
变量使用 32 位，替换为 double 则使用 64 位。

\subsection{半精度、单精度与双精度的差异}

半精度（FP16）是一种二进制浮点格式，在内存中占用 16 位（2 个字节），数值精度较低，但所需的计算资源更少，适用于机器学
习和图形处理等对精度要求不高的应用。

单精度（FP32）在内存中占用 32 位，在速度和精度之间取得了很好的折衷，因此成为各类计算任务的首选。

双精度（FP64）则被视为精度上的强劲引擎。在科学计算和复杂仿真中，每一个小数点都可能引发蝴蝶效应，因此这类应用依赖 
FP64 的高精度来确保对气候模式、分子结构等现象的仿真尽可能接近现实。不同的精度层级使 GPU 能够灵活适应各种行业和应用场
景。

\subsection{PI的精度对比}

研究显示，双精度计算需要四个执行周期，而单精度仅需两个周期——双精度虽然更慢，但提供了更高的精度。例如，声明 float 变量
X、Y、Z，设 X = 10.3，Y = 5.8，执行 Z = X + Y，该加法操作仅需两个周期；如果将类型替换为 double，同样的加法操作则需要四
个周期。这种差异源于双精度数据类型更高的精度和处理需求。

这类数值可能被近似为零而无法准确表示。
