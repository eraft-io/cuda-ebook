\section{基于二维线程块与线程的矩阵加法}

本章进入课程第二阶段：从一维线程块扩展到二维线程块，并将之应用于二维矩阵加法。前文所有示例（向量加法）仅使用 \texttt{blockDim.x} 与 \texttt{gridDim.x} 两个一维配置；处理矩阵时需引入 \texttt{blockDim.y} 与 \texttt{gridDim.y}，并解决二维索引到一维内存地址的映射问题。

\subsection{二维线程块配置}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{resources/cuda-118.png}
    \caption{一维与二维线程块配置对比：一维时 \texttt{blockDim.x} 最大 1024、\texttt{gridDim.x} 可达数千；二维时 \texttt{block = (32, 32)}、\texttt{grid = (1024, 1024)}，两维各自取值}
    \label{fig:ch33-2d-config}
\end{figure}

CUDA 提供四类内建变量描述线程块与网格的维度：

\begin{center}
\begin{tabular}{|p{4cm}|p{8cm}|}
\hline
\textbf{变量} & \textbf{含义} \\
\hline
\texttt{blockDim.x/y} & 线程块在 X、Y 维度的线程数 \\
\hline
\texttt{gridDim.x/y} & 网格在 X、Y 维度的线程块数 \\
\hline
\texttt{threadIdx.x/y} & 块内线程在 X、Y 维度的索引 \\
\hline
\texttt{blockIdx.x/y} & 网格内线程块在 X、Y 维度的索引 \\
\hline
\end{tabular}
\end{center}

二维配置的关键约束是：\textbf{\texttt{blockDim.x} 与 \texttt{blockDim.y} 的乘积不得超过 1024}（Ampere 架构上限）。例如 \texttt{(32, 32)} 合法（乘积 1024），\texttt{(1024, 2)} 非法（乘积 2048，编译通过但启动失败）。两维取值可自由调整，如 \texttt{(64, 16)}、\texttt{(128, 8)} 等，每种组合都可能影响性能，需实测择优。

\subsection{行主序内存存储}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\linewidth]{resources/cuda-119.png}
    \caption{矩阵加法 $C = A + B$：对应位置的元素逐一相加}
    \label{fig:ch33-matrix-add}
\end{figure}

矩阵加法 $C = A + B$ 逐元素相加（图~\ref{fig:ch33-matrix-add}），逻辑简单。难点在于：矩阵在代码中是二维的，而显存是一维的——需明确二维元素如何存储到一维内存中。

CUDA 采用\textbf{行主序（Row-major）}存储：矩阵每一行的元素在内存中连续排列。以图~\ref{fig:ch33-index-map} 为例，第一行元素 $4, 7, 9, 0, 2$ 依次存入地址 $0$--$4$，第二行紧接其后存入地址 $5$--$9$，以此类推。这样，二维矩阵被"铺平"为一维数组，行与行首尾相接。

\subsection{二维索引映射}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{resources/cuda-120.png}
    \caption{二维坐标 $(i, j)$ 到一维内存索引的映射：元素值 25 的坐标为 $i=3, j=1$，行宽为 5，内存索引 $= j \times \text{row\_size} + i = 1 \times 5 + 3 = 8$}
    \label{fig:ch33-index-map}
\end{figure}

行主序下，二维坐标 $(i, j)$（列 $i$、行 $j$）映射到一维内存索引的公式为：

\[
\text{index} = j \times \text{row\_size} + i
\]

其中 \texttt{row\_size} 为每行的元素数（列数）。以图~\ref{fig:ch33-index-map} 为例，元素 25 位于第 1 行第 3 列（$j=1, i=3$），行宽为 5，故 $\text{index} = 1 \times 5 + 3 = 8$，与内存地址 8 对应。

\subsection{从一维到二维的索引扩展}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{resources/cuda-121.png}
    \caption{一维索引公式 $ix = \texttt{threadIdx.x} + \texttt{blockIdx.x} \times \texttt{blockDim.x}$ 的回顾，及二维扩展：$ix$ 定位行内元素，$iy$ 定位具体行}
    \label{fig:ch33-1d-to-2d}
\end{figure}

一维向量加法中，线程索引公式为（图~\ref{fig:ch33-1d-to-2d} 上半部分）：

\[
ix = \texttt{threadIdx.x} + \texttt{blockIdx.x} \times \texttt{blockDim.x}
\]

扩展到二维矩阵时，行内位置仍用 $ix$ 计算（公式相同），再增加 $iy$ 定位具体行（图~\ref{fig:ch33-1d-to-2d} 下半部分）：

\[
iy = \texttt{threadIdx.y} + \texttt{blockIdx.y} \times \texttt{blockDim.y}
\]

最终内存索引将 $ix$、$iy$ 与矩阵列数 $nx$ 结合：

\[
\text{index} = iy \times nx + ix
\]

\subsection{二维矩阵配置实例}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\linewidth]{resources/cuda-122.png}
    \caption{$6 \times 8$ 矩阵的二维配置实例：网格 $3 \times 2$（6 块），每块 $4 \times 2$（8 线程），共 48 元素。以元素 44 为例，$ix = 0 + 1 \times 4 = 4$，$iy = 1 + 2 \times 2 = 5$，$\text{index} = 5 \times 8 + 4 = 44$}
    \label{fig:ch33-config-example}
\end{figure}

以 $6 \times 8$ 矩阵为例（图~\ref{fig:ch33-config-example}），三要素需对应：

\begin{itemize}
    \item \textbf{矩阵大小}：6 行（$0$--$5$）$\times$ 8 列（$0$--$7$），共 48 元素。
    \item \textbf{线程块与线程}：网格 $3 \times 2$（6 块），每块 $4 \times 2$（8 线程），即 \texttt{blockDim.x = 4}、\texttt{blockDim.y = 2}、\texttt{gridDim.x = 3}、\texttt{gridDim.y = 2}。
    \item \textbf{内存索引}：48 个元素按行主序编号 $0$--$47$。
\end{itemize}

以元素 44 为例验证映射：该元素位于块 $(1, 2)$ 内，块内线程索引为 $(0, 1)$。计算 $ix = 0 + 1 \times 4 = 4$，$iy = 1 + 2 \times 2 = 5$，$\text{index} = 5 \times 8 + 4 = 44$，与内存索引吻合。

\subsection{二维矩阵加法示例代码}

\begin{lstlisting}[language=C]
#include <stdio.h>
#include <cuda_runtime.h>

// 二维矩阵加法核函数
__global__ void matrix_add(const float* A, const float* B,
                           float* C, int nx, int ny) {
    int ix = threadIdx.x + blockIdx.x * blockDim.x;
    int iy = threadIdx.y + blockIdx.y * blockDim.y;
    if (ix < nx && iy < ny) {
        int idx = iy * nx + ix;      // 二维坐标 -> 一维内存索引
        C[idx] = A[idx] + B[idx];
    }
}

int main() {
    int nx = 4096, ny = 4096;
    size_t bytes = (size_t)nx * ny * sizeof(float);

    float *h_A = (float*)malloc(bytes);
    float *h_B = (float*)malloc(bytes);
    float *h_C = (float*)malloc(bytes);
    for (int i = 0; i < nx * ny; i++) {
        h_A[i] = 1.0f;
        h_B[i] = 2.0f;
    }

    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, bytes);
    cudaMalloc(&d_B, bytes);
    cudaMalloc(&d_C, bytes);
    cudaMemcpy(d_A, h_A, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, bytes, cudaMemcpyHostToDevice);

    // 二维块大小与网格大小
    dim3 block(32, 32);                          // 每块 1024 线程
    dim3 grid((nx + block.x - 1) / block.x,
              (ny + block.y - 1) / block.y);     // 128 x 128

    matrix_add<<<grid, block>>>(d_A, d_B, d_C, nx, ny);
    cudaDeviceSynchronize();

    cudaMemcpy(h_C, d_C, bytes, cudaMemcpyDeviceToHost);
    printf("C[0]=%.1f, C[last]=%.1f\n", h_C[0], h_C[nx*ny-1]);

    cudaFree(d_A); cudaFree(d_B); cudaFree(d_C);
    free(h_A); free(h_B); free(h_C);
    return 0;
}
\end{lstlisting}

关键点说明：

\begin{itemize}
    \item 核函数中 \texttt{ix}、\texttt{iy} 分别由 \texttt{threadIdx} 与 \texttt{blockIdx} 在 X、Y 维度计算，与一维公式结构相同。
    \item \texttt{idx = iy * nx + ix} 即行主序映射公式，将二维坐标转换为一维内存索引。
    \item \texttt{if (ix < nx \&\& iy < ny)} 为越界检查，处理矩阵维度非块大小整数倍的情况。
    \item \texttt{dim3} 类型用于指定二维配置：\texttt{block(32, 32)} 设定每块线程数，\texttt{grid(...)} 按向上取整计算网格块数。本例 $4096 / 32 = 128$，故 \texttt{grid} 为 $128 \times 128$。
    \item 总线程数 $= 32 \times 32 \times 128 \times 128 = 16{,}777{,}216$，恰等于 $4096 \times 4096$ 元素数，无空闲线程。
\end{itemize}

\subsection{性能分析与块大小优化}

用 \texttt{ncu} 分析上述程序，调整块大小可显著影响性能。以 \texttt{block(32, 32)} 与 \texttt{block(16, 16)} 两种配置对比：

\begin{center}
\begin{tabular}{|p{2.5cm}|p{2.2cm}|p{2.2cm}|p{2.8cm}|p{2cm}|}
\hline
\textbf{块大小} & \textbf{每块线程} & \textbf{每块 Warp} & \textbf{每 SM 活动块} & \textbf{占用率} \\
\hline
\texttt{(32, 32)} & 1024 & 32 & 1 & 50\% \\
\hline
\texttt{(16, 16)} & 256 & 8 & 6 & 74\% \\
\hline
\end{tabular}
\end{center}

\texttt{(32, 32)} 时每块达 1024 线程（32 个 Warp），SM 资源被单块占满，每 SM 仅能驻留 1 个块，占用率仅 50\%。改为 \texttt{(16, 16)} 后，每块仅 256 线程（8 个 Warp），SM 可同时驻留 6 个块，占用率升至 74\%，执行时间相应缩短。

可见，\textbf{块大小并非越大越好}：过大的块会耗尽 SM 的寄存器与调度资源，限制可并发驻留的块数，反而降低占用率。应在满足元素覆盖的前提下，选择使每 SM 活动块数最大化的块大小配置。本例中 L1 命中率约 1\%（几乎为 0，因未使用共享内存）、L2 命中率约 33\%，两种配置下基本一致——块大小主要影响占用率与调度，对缓存命中率影响较小，后者将在后续章节讨论。

\subsection{本章小结}

\begin{itemize}
    \item 二维线程块引入 \texttt{blockDim.y}、\texttt{gridDim.y}，约束为 \texttt{blockDim.x $\times$ blockDim.y $\leq$ 1024}。
    \item 行主序存储下，二维坐标 $(ix, iy)$ 映射到一维内存索引：$\text{index} = iy \times nx + ix$。
    \item $ix$、$iy$ 分别由 X、Y 维度的 \texttt{threadIdx} 与 \texttt{blockIdx} 按与一维相同的公式计算。
    \item 块大小影响占用率：过大的块（如 32$\times$32）使每 SM 仅驻留 1 块，占用率低；较小的块（如 16$\times$16）允许多块并发，占用率更高。
    \item 核函数需以 \texttt{if (ix < nx \&\& iy < ny)} 做越界检查，处理非整数倍维度。
\end{itemize}
