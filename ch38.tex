int main() {
    int n = 1024 * 1024;
    size_t size = n * sizeof(float);
    // allocate a space for the input vector on cpu and gpu
    float* d_input;
    float* h_input = new float[n];
    cudaMalloc(&d_input, size);

    // initialize the input vector on the host side
    for (int i = 0; i < n; i++) {
        h_input[i] = static_cast<float>(i);
    }

    // copy the host data to the device
    cudaMemcpy(d_input, h_input, size, cudaMemcpyHostToDevice);

    // edit the kernel configurations (block size the grid size)
    int blocksize = 256;
    int gridsize = (n + blocksize - 1) / blocksize;
    std::cout << gridsize << std::endl;

    // execute the cpu function
    float sum = cpu_reduce(h_input, n);
    std::cout << sum << std::endl;

    // launch the gpu kernel
    reduce_in_place<<<gridsize, blocksize>>>(d_input, n);
    cudaDeviceSynchronize();

    // launch the second kernel
    reduce_in_place<<<4096 / blocksize, blocksize>>>(d_input, 4096);
    cudaDeviceSynchronize();

    // launch the third kernel
    reduce_in_place<<<1, blocksize>>>(d_input, 16);
    cudaDeviceSynchronize();

    // copy the result from device to host
    cudaMemcpy(h_input, d_input, sizeof(float), cudaMemcpyDeviceToHost);

    std::cout << "GPU output: " << h_input[0] << std::endl;

    // free allocated space
    cudaFree(d_input);
    delete[] h_input;

    return 0;
}
\end{lstlisting}

但如果看第二个 kernel，

所以我们只需要 16 个 SM，这仅仅是一个波次（one wave）。

每个 SM 执行完一个 block 后就结束了，不会再执行其他任务。

例如 ALU 的利用率、FMA 的利用率、内存吞吐量等。

这是一个时间轴图。

这意味着它展示了应用程序执行过程中发生的情况。

有时平均活跃 block 数量会增加，有时会减少。

这个图表对于理解瓶颈非常重要，比如什么时候出现了下降，什么时候达到了最大值。

这也是不同算术单元利用率的图表。

例如 ALU、FMA、双精度和张量核心的利用率。

我们这里没有任何双精度运算，因为我们使用的是 float。

这就是为什么我们在 ALU 和 FMA 上有数值，而在双精度上没有。

如果你将 float 改为 double（并且需要在整个应用程序中进行更改），

你就会在这里看到双精度利用率的数值。

这是内存层级的图表。

例如，L1 命中率是 91%，L2 命中率是 80%。

如果你还记得向量加法（vector addition）的例子，我曾说过 L1 和 L2 的命中率是 0%。

那是因为在向量加法中，每个元素只被使用了一次。

但在这里，请看这个图。

在第一步中，我们使用了第一个和第二个元素。

在第二步中，我们再次使用了第一个元素以及另一个元素。

而第一个元素在第一步中已经被使用过了。

所以每个元素（比如位置 0）几乎在所有步骤中都被多次重用。

这就是为什么我们在这里有数据重用。

这也是为什么在 Nsight Compute 分析中会有缓存命中。

L2 命中率几乎是 80%。

这是从全局内存移动到 L2 的数据量。

这是从 L2 到 L1 的数据量，以及从 L1 到计算单元的数据量等等。

你需要观看 profiling 章节才能理解所有这些信息的含义。
