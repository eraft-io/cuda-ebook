\section{性能分析方法论}

本章建立一套可复现的性能分析方法论：通过系统地改变核函数的块大小（Block Size），观察其对各性能指标的影响，并用 Python 脚本自动化完成采集与绘图。实验对象仍是向量加法核函数——将两个向量相加并存入第三个向量，核函数的网格块数由命令行传入的块大小决定。

\subsection{实验设置与块大小参数}

CUDA 核函数的启动配置由两个参数决定：每个块的线程数（块大小）与网格中的块数。本实验将块大小从 32（一个 Warp）到 1024（CUDA 架构允许的最大块大小）以步长 32 递增，共 32 组配置。网格块数按如下公式计算，确保线程总数等于元素总数：

\begin{lstlisting}[language=C]
int block_size = atoi(argv[1]);          // 从命令行读取块大小
int grid_size  = (N + block_size - 1) / block_size;
vector_add<<<grid_size, block_size>>>(d_a, d_b, d_c, N);
\end{lstlisting}

编译与单次运行方式如下（块大小作为命令行参数传入）：

\begin{lstlisting}
nvcc -o test_01 test_01.cu
./test_01 256
\end{lstlisting}

\subsection{Python 自动化分析脚本}

若手动对 32 组配置逐一运行 \texttt{ncu}、再人工抄录指标到 Excel，既耗时又易错。正确的做法是用 Python 脚本驱动 \texttt{ncu} 完成全部采集、解析与绘图。脚本需采集的指标及其含义如下：

\begin{center}
\begin{tabular}{|p{6.8cm}|p{5.2cm}|}
\hline
\textbf{ncu 指标名} & \textbf{含义} \\
\hline
\texttt{\seqsplit{gpu\_\_time\_duration.avg}} & 核函数执行时间（纳秒） \\
\hline
\texttt{\seqsplit{sm\_\_cycles\_active.avg}} & 活动周期数 \\
\hline
\texttt{\seqsplit{l1tex\_\_t\_sector\_hit\_rate.pct}} & L1/纹理缓存扇区命中率 \\
\hline
\texttt{\seqsplit{lts\_\_t\_sector\_hit\_rate.pct}} & L2 缓存扇区命中率 \\
\hline
\texttt{\seqsplit{sm\_\_warps\_active.avg.pct\_of\_peak\_sustained\_active}} & 已实现占用率 \\
\hline
\texttt{\seqsplit{smsp\_\_sass\_average\_branch\_targets\_threads\_uniform.pct}} & 分支效率 \\
\hline
\texttt{\seqsplit{dram\_\_throughput.max.pct\_of\_peak\_sustained\_elapsed}} & DRAM 吞吐量占峰值比 \\
\hline
\end{tabular}
\end{center}

完整的自动化分析脚本 \texttt{get\_insight.py} 如下。它对每个块大小构造 \texttt{ncu --metrics ... --csv} 命令，用 \texttt{subprocess} 执行，解析 CSV 输出提取指标值，写入 \texttt{results.csv}，最后用 matplotlib 绘制各指标随块大小变化的图表：

\begin{lstlisting}[language=Python]
#!/usr/bin/env python3
"""
get_insight.py -- 自动化性能分析脚本

使用 Nsight Compute CLI (ncu) 对不同块大小的 CUDA 核函数
采集性能指标，导出 CSV 并绘制指标随块大小变化的图表。

用法:  python3 get_insight.py [可执行文件]
示例:  python3 get_insight.py ./test_01
"""

import csv
import io
import os
import subprocess
import sys

import matplotlib.pyplot as plt

# ---- 配置 ----
# 目标可执行文件（运行时接受块大小作为第一个命令行参数）
EXECUTABLE = sys.argv[1] if len(sys.argv) > 1 else "./test_01"

# 块大小范围: 32(一个 Warp) 到 1024(最大块大小), 步长 32
BLOCK_SIZES = list(range(32, 1025, 32))

# 待采集的指标: (ncu 指标名, 图表显示标签)
METRICS = [
    ("gpu__time_duration.avg",
     "GPU Time Duration"),
    ("sm__cycles_active.avg",
     "Active Cycles"),
    ("l1tex__t_sector_hit_rate.pct",
     "L1 Hit Rate (%)"),
    ("lts__t_sector_hit_rate.pct",
     "L2 Hit Rate (%)"),
    ("sm__warps_active.avg.pct_of_peak_sustained_active",
     "Achieved Occupancy (%)"),
    ("smsp__sass_average_branch_targets_threads_uniform.pct",
     "Branch Efficiency (%)"),
    ("dram__throughput.max.pct_of_peak_sustained_elapsed",
     "DRAM Throughput (%)"),
]

# 逗号分隔的指标名列表, 传给 ncu --metrics
METRIC_NAMES = ",".join(m[0] for m in METRICS)

OUTPUT_CSV = "results.csv"
OUTPUT_DIR = "charts"


def run_ncu(block_size):
    """对单个块大小执行 ncu, 返回 CSV 文本输出。"""
    cmd = [
        "ncu",
        "--metrics", METRIC_NAMES,
        "--csv",
        EXECUTABLE, str(block_size),
    ]
    print(f"[*] Profiling block size = {block_size} ...")
    proc = subprocess.run(cmd, capture_output=True, text=True)
    return proc.stdout


def parse_metrics(csv_text):
    """从 ncu 的 --csv 输出中提取 {指标名: 数值} 字典。"""
    # 过滤 ==PROF== 等非 CSV 行
    lines = [ln for ln in csv_text.splitlines()
             if not ln.startswith("==PROF==") and ln.strip()]
    if not lines:
        return {}
    reader = csv.reader(io.StringIO("\n".join(lines)))
    header = next(reader)
    # 定位 Metric Name 与 Metric Value 列
    idx_name = header.index("Metric Name")
    idx_value = header.index("Metric Value")
    result = {}
    for row in reader:
        if len(row) <= max(idx_name, idx_value):
            continue
        result[row[idx_name]] = row[idx_value]
    return result


def main():
    os.makedirs(OUTPUT_DIR, exist_ok=True)

    # CSV 表头: Block Size + 各指标标签
    header = ["Block Size"] + [label for _, label in METRICS]
    rows = []

    for bs in BLOCK_SIZES:
        csv_text = run_ncu(bs)
        values = parse_metrics(csv_text)
        row = [bs]
        for metric_name, _ in METRICS:
            row.append(values.get(metric_name, ""))
        rows.append(row)

    # 写入 results.csv
    with open(OUTPUT_CSV, "w", newline="") as f:
        writer = csv.writer(f)
        writer.writerow(header)
        writer.writerows(rows)
    print(f"[+] CSV 已写入 {OUTPUT_CSV}")

    # 逐指标绘图
    block_sizes = [r[0] for r in rows]
    for metric_name, label in METRICS:
        ys = []
        for r in rows:
            try:
                ys.append(float(r[header.index(label)]))
            except (ValueError, TypeError):
                ys.append(0.0)
        plt.figure(figsize=(8, 5))
        plt.plot(block_sizes, ys, marker="o")
        plt.xlabel("Block Size")
        plt.ylabel(label)
        plt.title(f"{label} vs Block Size")
        plt.grid(True)
        fname = label.replace(" ", "_").replace("/", "_")
        out = os.path.join(OUTPUT_DIR, f"{fname}.png")
        plt.savefig(out, dpi=120)
        plt.close()
        print(f"[+] 图表已保存 {out}")


if __name__ == "__main__":
    main()
\end{lstlisting}

运行脚本即可一次性完成全部采集与绘图：

\begin{lstlisting}
python3 get_insight.py ./test_01
\end{lstlisting}

脚本的工作流程为：对每个块大小（32、64、96、\ldots、1024）构造 \texttt{ncu --metrics <指标列表> --csv ./test\_01 <块大小>} 命令；用 \texttt{subprocess.run} 执行并将标准输出存入 \texttt{result}；过滤掉 \texttt{==PROF==} 前缀的非 CSV 行后，用 \texttt{csv} 模块按 \texttt{Metric Name} 与 \texttt{Metric Value} 列提取指标值；将每个块大小对应的指标值写入 \texttt{results.csv} 的一行；最后为每个指标绘制一张"指标值 vs 块大小"的折线图并保存为 PNG。\texttt{--csv} 选项使输出以逗号分隔而非表格，便于程序解析。

\subsection{波次与执行时间分析}

要理解块大小 32 为何最慢，需引入\textbf{波次（Wave）}的概念。波次指一个 SM 在同一时刻能够同时驻留并调度的块数，其上限即占用率分析中的"已分配活动块数"（Allocated Active Blocks）。本例 GPU 有 38 个 SM，每 SM 的已分配活动块数为 16。

以块大小 32 为例，总块数为 $N / 32$（数百万）。每个 SM 分担的块数为：

\[
\text{每 SM 块数} = \frac{\text{总块数}}{\text{SM 数}} = \frac{N / 32}{38}
\]

由于每 SM 同时只能驻留 16 个块，剩余块必须排队等待，分多个波次依次执行：

\[
\text{每 SM 波次数} = \frac{\text{每 SM 块数}}{16}
\]

用 \texttt{ncu} 采集可得每 SM 波次数，与上式计算结果一致。当块大小增至 64 时，总块数减半，每 SM 块数减半，但每块含 2 个 Warp，单波次内可调度的 Warp 数翻倍——这正是性能差异的根源。

\subsection{块大小对性能的影响}

设想同一 SM 在块大小 32 与 64 两种配置下：两种情况的已分配活动块数都是 16，但块大小 32 的每个块仅含 1 个 Warp，而块大小 64 的每个块含 2 个 Warp。

核函数中存在内存操作（\texttt{LDG.E} 加载）与依赖它的加法（\texttt{IADD3}）之间的数据依赖。内存操作的延迟远高于算术操作：L1 命中约 30 周期，L2 命中约 200 周期，全局内存命中可达 300--400 周期。当某个 Warp 因等待内存结果而停顿时：

\begin{itemize}
    \item \textbf{块大小 32}：每块仅 1 个 Warp，该 Warp 停顿后，SM 在该块内无其他 Warp 可调度，只能空转或切换到其他块，停顿隐藏能力弱。
    \item \textbf{块大小 64}：每块 2 个 Warp，一个 Warp 停顿时，SM 可立即调度同块的另一个 Warp 继续执行，有效隐藏内存延迟，总执行时间更短。
\end{itemize}

这解释了图表中块大小 32 的执行时间与活动周期数显著偏高、而 64 之后趋于平稳的现象。核心结论是：\textbf{块大小决定了每块内的 Warp 数，进而决定了 SM 通过 Warp 调度隐藏延迟的能力}。后续章节将围绕这一机制展开更深入的性能优化实践。

\subsection{本章小结}

\begin{itemize}
    \item 性能分析应系统化：以块大小为变量、以 \texttt{ncu} 采集的指标为观测量，用 Python 脚本自动化完成采集、解析与绘图，避免人工重复操作。
    \item \texttt{get\_insight.py} 通过 \texttt{subprocess} 驱动 \texttt{ncu --metrics ... --csv}，用 \texttt{csv} 模块解析输出，写入 \texttt{results.csv} 并用 matplotlib 绘图，可复用于任意 CUDA 应用程序。
    \item 块大小 32（每块一个 Warp）时执行时间最长，原因是 SM 内可调度的 Warp 数不足，无法有效隐藏内存延迟；块大小增至 64 后，每块多 Warp 使延迟隐藏能力增强，性能趋于平稳。
    \item 波次数 = 每 SM 块数 / 已分配活动块数，是衡量核函数在 SM 上分批执行规模的关键指标。
\end{itemize}
